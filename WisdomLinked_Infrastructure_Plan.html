1. Executive Summary

This document outlines the plan to replace WisdomLinked's current custom Socket.IO chat and public Jitsi video calling with a self-hosted, enterprise-grade communications infrastructure using Rocket.Chat (real-time messaging) and Jitsi Meet (video conferencing), deployed on a dedicated DigitalOcean server.

The migration eliminates MAU (Monthly Active User) limits currently affecting video calls, resolves critical reliability issues in the chat system, and reduces long-term costs compared to paid alternatives.

Key Outcomes: Zero MAU limits • Offline message delivery • End-to-end encryption • Message search • Push notifications • Integrated video calling from chat • Full data ownership • ~$58/mo total infrastructure cost

6. Data Flow & Integration

6.1 User Registration Flow

User registers on WisdomLinked │ ▼ WisdomLinked Backend creates user in MongoDB │ ▼ Backend calls Rocket.Chat REST API ──▶ POST /api/v1/users.create │ (syncs username, email, role) ▼ User can now access chat via WisdomLinked UI

6.2 Chat Message Flow

User A sends message in WisdomLinked UI │ ▼ Request hits Rocket.Chat (via iframe embed OR REST API) │ ▼ Rocket.Chat stores message in its MongoDB │ ▼ Rocket.Chat pushes message to User B via WebSocket (managed by RC) │ ▼ If User B is offline: → Message queued in MongoDB → Push notification sent → Delivered on reconnect

6.3 Video Call Flow

User A clicks "Video Call" in chat │ ▼ Rocket.Chat creates Jitsi room link (meet.wisdomlinked.com/WisdomLinked_roomId) │ ▼ Notification sent to User B │ ▼ Both users connect to self-hosted Jitsi → No MAU limits → WebRTC peer-to-peer (or via JVB for 3+ users) → In-call chat available via Jitsi

6.4 Integration Approaches

8. Migration Plan

Phase 1 — Infrastructure (Week 1)

  • Provision DigitalOcean droplet (8GB/4vCPU)
  • Configure DNS records (chat.wisdomlinked.com, meet.wisdomlinked.com)
  • Install Docker, Nginx, Certbot
  • Deploy Rocket.Chat + MongoDB via Docker Compose
  • Deploy Jitsi Meet via Docker Compose
  • Configure Nginx reverse proxy + SSL
  • Configure Rocket.Chat admin settings
  • Connect Jitsi to Rocket.Chat

Phase 2 — Integration (Week 2)

  • Create Rocket.Chat service module in backend (user sync API)
  • Update auth controller to create RC users on registration
  • Implement chat embed (iframe or custom UI) in frontend
  • Update Jitsi domain from meet.jit.si to meet.wisdomlinked.com
  • Add environment variables to staging and production

Phase 3 — Cleanup & Testing (Week 3)

  • Remove Socket.IO server code (BE/socket/*)
  • Remove all socket controllers (BE/socketControllers/*)
  • Remove Socket.IO client code from frontend
  • Remove socket.io dependencies from package.json
  • End-to-end testing: 1:1 chat, group chat, file sharing, video calls
  • Test offline message delivery and push notifications
  • Load testing with concurrent users

Phase 4 — Deployment (Week 4)

  • Deploy to staging environment
  • QA testing on staging
  • Production deployment
  • Monitor for 48 hours post-deploy
  • Documentation handoff
